# Demo 与 workshop：怎么给非技术人讲技术取舍

**FDE-08** · **2026-11-09** · Day 8 · **主题板块** 需求发现 · **难度** 进阶

## 场景：一页纸签完了，现场演示翻车
接着物业报修那一单（第 7 课）。one-pager 签过了：第一期做「报修讯息自动分类 + 派单建议」，客服一键确认，不做住户聊天机器人。

今天你要给营运、客服主管和 IT 开一场 45 分钟的 workshop，现场用几条真实（脱敏）报修讯息演示分类效果，顺便敲定「置信度低于 70% 转人工」这件事。

结果开场你就讲了 10 分钟模型、embedding、准确率公式。营运经理打断：「咁同而家有咩分别？」客服主管只关心「会唔会派错工」。IT 想听对接，却被你绕进了向量库选型。

demo 翻车了不是因为模型不好，是因为**你在给工程师讲架构，却在给要拍板的人开会。**


## 类比：你在微博做过的功能评审
微博上线一个降级开关或缓存方案前，产品评审和技术评审是两场会：

- 技术评审：讲 QPS、一致性、回滚路径
- 产品 / 业务评审：讲用户会看到什么、坏了会怎样、要不要今天上

你不会把 p99 latency 的幻灯片原封不动扔给运营。你会改成：「高峰时发博变慢，用户会刷不出最新微博。」

FDE 的 demo / workshop 就是这场业务评审。听众是营运和 sponsor，技术细节留给事后的 IT 对接会。

另一个角度：它像一次「带着客户一起走 happy path 的 code review」——不是看 diff，是看他们自己的工作流在新方案里怎么走完。


## 原理

### 它解决什么问题
把已经写在 one-pager 上的取舍，变成**客户亲眼看见、亲手参与、当场能拍板**的共识。纸上点头不够；现场走一遍，分歧才会冒出来。

### 怎么工作：一场 45 分钟 workshop 的骨架
```
0–5   分钟  今天要决定什么（1–2 个决定，写在白板上）
5–15  分钟  用客户自己的场景走 happy path（只演示成功路径）
15–25 分钟  抛出 1–2 个取舍，每项用「得什么 / 失什么 / 改回来贵不贵」讲
25–35 分钟  让客户动手（贴便利贴、改置信度阈值、挑一条他们带来的讯息）
35–45 分钟  回收决定：谁同意、还缺什么、下一步谁做什么
```

**讲取舍的句式**（不要先扔技术名词）：

> 「方案 A：置信度低于 70% 就转人工。客服工作量会多一点，但派错单的风险更低。」
> 「方案 B：全部自动派。客服省事，但低置信度时可能派错，投诉会回来找你们。」
> 「我建议 A，因为第一期优先证明『不添乱』。需要你们今天定：用 70% 还是别的阈值。」

三个要素都要有：**得什么、失什么、改回来贵不贵**。缺第三点，客户以为以后随便改；其实模型阈值好改，流程习惯和培训成本不好改。

### Demo 的三条硬规矩
1. **用他们的场景，不用你的假数据**：脱敏后的真实报修讯息，比「Hello world 分类」有说服力一百倍。
2. **只走 happy path**：边缘 case、失败重试留给 IT 对接会。业务方要先看见「做成了长什么样」。
3. **先讲限制再演示**：开场就说「今天准确率大约八成、粤语夹杂英文的句子还在练」——中途翻车才说，信任就没了。

### 会在哪里坏
- **开场讲架构**：听众失焦，取舍讲不完，决定带不走。
- **没有明确的 Ask**：演示完大家鼓掌散场，置信度阈值没定、对接人没定。
- **Live demo 依赖外网 / 未脱敏数据**：现场断网或合规同事打断，整场报废。备一条录屏或本地假数据。
- **把 workshop 开成销售秀**：只秀亮点、不暴露限制，两周后客户说「你没说过会这样」。


## FDE 视角
- **怎么用**：one-pager 发出去之后尽快开。最好带着白板版一起填「需要的决定」那一栏（第 7 课第 8 栏），workshop 当天就能签。
- **客户常问**：「可唔可以再加个功能演示下？」答法：回到第 6 课的取舍——「可以记进 backlog，今天先把已签的范围走通；加东西要拿别的换，或者放二期。」
- **四类雇主差异**（对照即可）：
  - AI 原生 / 产品公司：demo 往往也是产品反馈入口，现场记「哪些该回流产品」
  - 大厂云与平台：多半要同时秀平台能力，但仍先讲客户结果，再点到用了哪项托管服务
  - 咨询与系统集成：workshop 纪要会进交付物，决定和出席人要写进会议记录
  - 甲方企业内部：听众常有合规 / 内控，限制和数据流向必须开场就说清
- **常见坑**：
  - 只邀请 sponsor，客服和 IT 不在场，现场同意、落地时推翻
  - 用英文术语硬讲，听众是粤语 / 普通话习惯的营运（用对方习惯的语言讲，英文落纸）


## 面试怎么问
**题目**：「你要给非技术的业务方做一场 demo，同时让他们在两个技术取舍里选一个。你会怎么设计这场会？」

**答题思路**：先说目标（带走 1–2 个决定），再说结构（场景 → happy path → 取舍三要素 → 客户动手 → 回收决定），强调用客户自己的数据、先讲限制、不讲架构。可以类比微博的产品评审 vs 技术评审，说明你分得清听众。


## 一句话带走
**Demo / workshop 不是秀技术，是带着客户走一遍他们自己的工作流，用「得／失／改回来贵不贵」让他们当场签下取舍。**

## 自测

1. 如果 workshop 里你把模型结构、向量库选型和三条失败路径都讲完了，却没让客户定置信度阈值，散场后最可能发生什么？缺的是哪一步？
2. 如果你在 AI 原生 / 产品公司做 FDE，这场 workshop 除了帮客户拍板，还多出一个对内的用途是什么？你会怎么记下来？

**第 1 题**：散场后大家觉得「演示很厉害」，但关键参数没定，回去各写各的：你按 70% 做，客服按「尽量自动」理解，IT 按「全自动对接」排期。两周后对不上，又要重开一次会。缺的是开场就写在白板上的 Ask，以及结尾明确回收决定（谁同意、定了什么、下一步谁做什么）。
