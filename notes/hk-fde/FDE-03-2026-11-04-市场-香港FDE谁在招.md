# 香港 FDE 市场：谁在招、给多少、怎么定级

**FDE-03** · **2026-11-04** · Day 3 · **主题板块** 香港市场 · **难度** 入门

## 场景：一位招聘经理桌上的两份 CV
香港一家地产集团（虚构的例子）想在集团内部设 FDE，派到物业、租务、财务几个部门去落地 AI。招聘经理手上有两份 CV：

- **A**：10 年后端，大厂架构组，系统设计很强，但从没见过业务方以外的人，项目描述全是「QPS 从 X 到 Y」。
- **B**：5 年，做过两个 AI 落地项目，能讲清楚「我去理赔部坐了三天，发现真正的瓶颈不是模型，是扫描件」。

她最后给 B 开了 senior，给 A 开了 mid，或者干脆没给 A 面试。

为什么年限更长的人反而被压级？这就是今天要搞懂的：**香港 FDE 市场在为什么付钱。**

## 类比：从「写需求的人」到「服务 owner」
你在微博一定见过两种工程师：

- 一种是**接需求、写代码**的：需求写清楚了就做得很好，但需求本身对不对，不归他管。
- 另一种是**服务 owner**：一个服务出了事，半夜被 call 的是他；他会主动问「这个功能上线后，下游扛得住吗？」，对结果负责。

FDE 的 junior 和 senior，差的就是这个。只是 FDE 的「服务」换成了**一个客户的业务结果**。年限只是一个代理指标，市场真正在买的是：**你能独自对多大、多模糊的一块客户结果负责。**

## 原理

**它解决什么问题**
看懂市场，你才知道该把精力花在哪里：投哪类公司、怎么定级、简历讲什么故事。

**怎么工作：谁在招（2026 年 9–10 月香港真实岗位）**
```
AI 原生公司 / 海外独角兽设香港岗
  Retell AI（语音 AI）、Telnyx、Wonderful
  → 节奏快，产品成熟，要你独自扛客户
大厂云 / 平台
  ByteDance BytePlus、Alibaba Cloud
  → 客户多是大企业，金融、保险、零售都有
本地 AI 公司
  Fano Labs（粤语语音）、Votee AI、KBQuest
  → 政府、监管机构、内网 / air-gapped 部署多
甲方企业内部 FDE
  南丰 Nan Fung（地产）、Schonfeld（对冲基金）、Bullish
  → 「客户」是集团内部业务部门，要懂行业
咨询
  Deloitte Digital
  → 项目制，跨行业
```
招聘顾问 Morgan McKinley 的观察是：香港需求最旺的是**银行金融**，其次是**地产 / 物业科技**、媒体娱乐、物流。原因是香港老系统多、数据多在本地机房、监管严，很需要能「下到现场」的人。

**给多少（月薪，HKD，base）**
- Morgan McKinley（2026-09）：
  - Mid（3–5 年）：50K–70K
  - Senior（6–9 年）：70K–95K
  - Principal / Lead（10 年以上）：95K–130K+
- Jobstore 按招聘广告汇总（2026-11-04 更新）：平均约 70.6K，区间 45K–120K。这些多是平台估算，只能当参考。

**年限要求怎么写**：Alibaba Cloud 3 年以上，Fano Labs 3–6 年，KBQuest 和 Schonfeld 都是 5 年以上。真正的分水岭不在年限，在下面这张表：

| | Junior / Mid | Senior |
|---|---|---|
| 范围 | 别人定好 scope，你交付 | 你自己去问出 scope |
| 面对谁 | 客户的工程师 | 客户的业务负责人、IT、合规 |
| 出事时 | 上报 | 自己判断、取舍、扛 |
| 证据 | 「我实现了…」 | 「我发现了…所以改成…结果指标…」 |

**关键取舍：你会在哪里「坏」**
把你自己放进来看：

- **你的硬底子**：8 年后端 / 架构，正好压在生命周期的 **production** 那一段：高并发、稳定性、降级、监控。很多从咨询或售前转过来的 FDE，恰恰缺这一块。
- **你的加分项**：2026 年刚读完硕士，LLM 知识新；做过 AI 内容运营，知道 AI 输出「好不好用」是用户说了算。普通话加内地大厂背景，对 Telnyx 这类明确要跑大中华区的岗位，以及中资云厂商，是加分项。
- **最容易被压级的地方**：简历如果全是 QPS 和架构图，招聘方会把你读成「很强的 A」，也就是 mid。缺的是 **discovery** 和 **adoption** 两头的故事：你怎么问出真需求，上线后怎么让人真的用起来。
- **要核对的技术栈**：JD 最常见的是 Python + TypeScript、REST API、SQL、云和 Docker/K8s、LLM 应用（RAG、Agent、evals）。哪块你还不熟，后面的课正好补上。

## FDE 视角
- **怎么用这张地图**：先选 1–2 类雇主重点投，不要每类都撒一点。比如想发挥架构优势，就看大厂云和本地 AI 公司的内网部署岗；想走行业路线，就看银行或地产甲方。
- **招聘方常问**：「你没正式做过 client-facing，凭什么做 FDE？」你的底牌是：在微博，产品、运营、业务方就是你的「客户」。
- **常见坑**：
  - 按年限直接报 senior 的价，但拿不出一个「对结果负责」的故事；
  - 把 FDE 当成「会写 prompt 的售前」，面试时代码和系统设计反而没准备；
  - 忽略语言要求：不少 JD 写明要英文，有些也要粤语或普通话，投之前先看清楚。

## 面试怎么问
**题目**：「你 8 年都在做内部平台，几乎没直接面对外部客户。为什么你觉得自己能做 FDE？」

**答题思路**：别否认差距。先把内部业务方重新讲成「客户」，再用一个 STAR 故事讲你怎么把一个模糊需求问清楚、推上生产、看到指标变化，最后说你正在怎么补 client-facing 的部分。

## 一句话带走
**香港 FDE 的级别不按年限算，按你能独自对多大一块客户结果负责来算。你的 8 年架构经验是 production 段的硬底子，要补的是 discovery 和 adoption 两头的故事。**

## 自测

1. 为什么同样 8 年经验，一个只在后端写代码的人，可能只拿到 mid-level FDE 的 offer？如果你是面试官，会看哪些信号判断他够不够 senior？
2. 同样一份 8 年后端经历，投 AI 原生公司和投甲方银行内部 FDE，简历第一段应该分别突出什么？

**第 1 题**：因为 FDE 的级别看的是「能独自对多大一块客户结果负责」。只写代码的人，证据都在 production 段，缺少自己去问出 scope、面对业务和合规、上线后推动使用的经历，面试官会把他放在「别人定好需求、他来交付」那一档。面试官会看：能不能讲清一个从模糊需求到上线的完整故事；有没有用业务指标说明结果；出问题时自己做过什么取舍；能不能跟非技术的人讲清楚技术方案。

**第 2 题**：AI 原生公司：突出速度和端到端，比如「两周内从需求到上线」、做过的 LLM / RAG 项目、能独立面对客户。甲方银行：突出稳定性、安全和合规意识，比如高可用、权限、审计、变更流程，以及跟业务部门协作推动上线的经历。技术底子一样，开头讲的故事不一样。
