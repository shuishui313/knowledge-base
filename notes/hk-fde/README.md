## 收录约定

- 一篇短课一个 Markdown 文件。文件名从一开始就带编号：`FDE-NN-YYYY-MM-DD-主题简述.md`。`NN` 与 Day 相同，两位数字。新短课用下一个编号。已分配的编号不复用、不重排
- 同一编号写在文首，并出现在本文件和 `README.en.md` 的 `编号` / `No.` 列
- 结构保持：文首写编号、日期、Day、主题板块、难度；然后是场景、概念、香港落地例子、面试怎么说、小练习、两道自测。自测后用 `<details><summary>参考答案</summary>`
- 以香港 FDE 招聘要考的内容为主。答案按公司类型分开：虚拟银行/保险、物流、公营柜面、AI 产品或解决方案公司。一种公司写透，其余用一张对照表。公开面经只写核对得了的常见问法，并标明「公开面经里的常见问法」；不编造某家银行或保险公司的原话、候选人故事或逐字题。招聘层写完可以有短的「拓展补充」。「面试怎么说」大约一分钟：候选人可以说出口的英文，并写明现场用粤语讲清楚、用英文把确认写下来。自测仍是两题，其中一题要问面试官换成另一类公司时答案怎么变
- 相关 YouTube 可选，放在参考答案之后、系列导航之前的 `延伸观看`。同一系列同一天最多 2 条。只收相对热门的解说、一节短课，或有见解的分享。普通的长课、泛泛的网课不收。没有合格的就省略这一节，不凑数。不写播放量
- 新增时放入文件，并在本文件和 `README.en.md` 的表里各加一行。步骤见 [fde-daily-lesson](../../examples/recipes/fde-daily-lesson/README.md)
