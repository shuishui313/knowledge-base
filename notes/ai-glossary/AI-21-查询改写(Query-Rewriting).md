**AI-21**

## 面试在问什么

物业报修助手已经会分流，也会在有依据时才引用。上线之后，新的问题往往不是「搜得不够像」，而是「用户那句话本身就不适合拿去检索」。

住户刚查过 WO-3184，接着用粤语问「个水喉仲漏唔漏？」。原话直接去检索，可能翻到渗漏处理手册；改写如果改歪了，又会丢掉工单号，变成一句空泛的「漏水怎么处理」。另一次，住户说「取消 15A 的临时通行证」，被改写成「如何申请临时通行证」，答了一套申请流程。还有一次，系统先让模型写了一段假想的「按金五十元」通告去检索，随后把这段假想文字一并交给了住户。

面试官很少停在「我们做了 query rewrite」。公开面经里的常见问法围着这几件转：改写和路由是不是一回事？指代和粤语口语怎么处理？多改写几句会不会把问题改歪？HyDE 写出来的假想文档能不能当证据？这一层怎么验收？

只说「先让模型把问题写得更清楚再检索」，偏弱。能讲清查询改写是上路之后把问法变得更好找、原话里的约束必须留下来、假想文档只用来检索不能当答案、改写忠实度和回答质量要分开验收，才像 FDE。

[查询路由](AI-19-查询路由(Query-Routing).md) 决定走哪条路。这篇写上路之后、检索或查系统之前的那一层：用户那句话，怎样变成这一路真正该用的查询。检索之后留下哪几条进提示词，见 [重排序](AI-22-重排序(Reranking).md)。找到材料之后，仍要按 [引用与溯源](AI-20-引用与溯源(Grounding-and-Citation).md) 核对依据。

## 定义

查询改写（Query Rewriting，也常叫查询翻译 / Query Translation，或查询变换 / Query Transformation）：在已经选定的路径上，把用户的原话变成一条或几条更适合检索、或更适合传给工具的查询。它改的是「怎么找」，不是「去哪里找」，也不是「用哪一个生成模型」。

常见手法有几类，目的都是同一件：让查询更接近这一路资料或接口真正能匹配的形式。

| 做法 | 决定什么 | 不是什么 |
|------|----------|----------|
| 查询改写 | 在已选定的路上，把原话变成更好找的查询 | 不决定该走手册还是工单系统 |
| 查询路由 | 这条问题走哪条路径 | 不负责把口语改写成检索词 |
| 多查询（Multi-query） | 同一意图写成几句不同的检索问法，分别检索再合并 | 不是把两个意图塞进一次检索交差 |
| 假设文档嵌入（HyDE） | 用一篇假想文档的向量去检索真实片段 | 不是把假想文档当作证据或答案 |

先选路，再按需要改写，见 [查询路由](AI-19-查询路由(Query-Routing).md)。把「换一个更大的模型」或「再搜一遍」当成改写，解决不了路走错、约束丢了的问题。

## 一次请求里实际发生了什么

1. 先路由，再改写。路还没定，不要先改写。查工单进度的，改写最多是把「那单」「个水喉」还原成 WO-3184，再交给工具；不要改成手册里的渗漏处理问法。见 [工具调用](AI-03-工具调用(Tool-Calling).md)。
2. 判断要不要改、怎么改。已经很清楚的书面问法，或带完整单号的系统查询，可以不改。需要改的常见有三类：补全指代和这一轮对话里的对象；把粤语、错字、口语对成这一路资料里的说法；同一意图写几句不同的检索问法，再合并去重。
3. 原话里的约束必须带过去：户号、取消还是申请、日期、栋座、工单号。改完要对回原问题；对不上就作废，改用原话检索，或问一句澄清，见 [人工在环](AI-15-人工在环(Human-in-the-Loop).md)。
4. 若使用 HyDE：模型根据问题写一篇「看起来像手册或通告」的假想段落，只拿它的向量去检索真实片段。这篇假想文字不得进入生成上下文，不得展示给用户，不得当作引用。真正的证据仍是检索到的现行材料，见 [引用与溯源](AI-20-引用与溯源(Grounding-and-Citation).md) 和 [嵌入与向量检索](AI-08-嵌入与向量检索(Embedding).md)。
5. 检索或查系统之后，权限、版本和依据规则不变。改写只改善怎么找，不降低依据标准，也不绕过过滤，见 [权限感知检索](AI-17-权限感知检索(Permission-aware-Retrieval).md)。个人和实时问题，不要改写成可拿去共用缓存的通用问法，见 [语义缓存](AI-18-语义缓存(Semantic-Caching).md)。
6. 记下原问题、改写后的查询、用了哪一种改写、约束有没有保住。事后才能分清是改写改歪了，还是检索或生成坏了，见 [可观测性](AI-16-可观测性(Observability).md) 和 [评测](AI-05-评测(Evaluation).md)。

## 会在哪里坏

常见不是「没做改写」，而是改写把路带偏了，或把原问题改丢了。

- **先改写、后路由，或改写改了路。** 「师傅到咗未」被改写成「一般多久到场」，走进旧 FAQ。这是路由问题被改写放大了，不是检索阈值没调好。
- **丢掉约束。** 「取消 15A 的临时通行证」变成「如何申请临时通行证」。字更像手册标题了，问题已经不是原来那件。
- **把上一轮上下文套到新问题上。** 刚查过 WO-3184，下一句其实在问今晚停不停水，系统仍把工单号填进去。上下文要用，但不能默认每一句都还在说上一件。
- **假想文档泄漏。** HyDE 为了检索写了「按金五十元」。这段话随后进了答案或角标。假想文档可以有错，正因如此它不能当证据。
- **多查询搅乱意图，或只涨成本和延迟。** 一句里既报修又查进度，改成许多问法后只合并进一次检索；或者无差别地扩成十几条查询，召回没有变好，费用和等待先上去了。
- **把个人或实时问题改写成可缓存的通用 FAQ。** 「我的单到边了」被改成「工单一般两小时内处理」，再命中了共用缓存。
- **验收只看最终答案好不好看。** 演示题答对了，看不出约束有没有保住，也看不出假想文档有没有漏进答案。要把「改写是否仍是原问题」做成冻结集，和检索质量、回答质量分开统计。

## 香港落地例子

继续那间虚构的沙田私人屋苑助手。数字、户号和通告编号都是编的，不代表任何机构。

住户刚问过 WO-3184 的进度，接着说「个水喉仲漏唔漏？」。正确的改写是：在工单系统里查 WO-3184 当前是否仍为渗漏、是否未完工。不要把它改写成「厕所地台渗水，住户可以先做什么」再去翻手册。手册可以稍后解释流程，但不能代替这一单此刻的状态。

住户用粤语问「点申请临时通行证」。这一路已经确定走手册，可以把问法对成现行条款里的标题，例如「申请临时访客通行证」，再检索、引用原文。如果原话是「取消 15A 的临时通行证」，改写必须保留「取消」和「15A」，不能变成申请流程。

不要把 HyDE 的假想段落给出去。系统可以先写一段「看起来像通告」的文字，只为了向量更接近真实通告；检索到的必须是现行通知。假想文里即使写了「按金五十元」，只要现行条款没写，就不能出现在答案或角标里。证据不够，就按溯源的规则明说没有，或转管理处。

验收时，冻结集里至少要有：粤语指代必须带回工单号并走系统的题、必须保留「取消」和户号的题、假想文档不得泄漏的题，以及下一句已经换题、不得沿用上一轮对象的题。只拿「怎样申请临时通行证」的标准书面题做演示，看不出这一层有没有坏。

四类雇主的差异（对照即可）：

| 雇主类型 | 这件事上的侧重点 |
|----------|------------------|
| AI 原生 / 产品公司 | 改写是带版本的链路一环；改提示词或模型前，要用含「约束必须留下」「假想文档不得泄漏」的冻结集做回归 |
| 大厂云与平台 | 托管知识库若默认改写每一句，要能配置「哪些路不改写」，并在追踪里看到原问题、改写后的查询和所用手法 |
| 咨询与系统集成 | 把改写范围、不得改路、证据不足时的动作，以及改写忠实度的验收写进范围；工时往往花在这些规则，而不是多写几条同义问法 |
| 甲方企业内部（如银行、保险、地产） | 账户、限额、工单状态必须带着客户号或单号去查系统；改写成产品说明或旧 FAQ，在审计里过不了 |

## 面试怎么说

> "Query rewriting happens after routing has already picked a path. It turns what the user said into one or more queries that are easier to retrieve or to send to a tool. It does not decide whether we search the handbook or look up a ticket. If a resident asks in Cantonese 'is that leak still going?' after talking about WO-3184, we resolve the reference and query the work-order system — we do not rewrite it into a generic leak FAQ. Constraints must survive: 'cancel the 15A visitor pass' cannot become 'how to apply for a pass'. Multi-query can paraphrase the same intent to raise recall, but it is still one intent. HyDE is different: a hypothetical document is only a search key. It is not evidence, and it must never be shown as the answer. We evaluate rewrite faithfulness on a frozen set — did the ticket id and the unit number survive — separately from final answer quality."

先把「改写」和「路由」拆开，再说约束必须留下、假想文档只用来检索；用客户习惯的语言（粤语或普通话）讲清楚，用英文把结论写下来。

## 小练习

仍是上面那间虚构的屋苑助手。同事报了三句「我们已经做了查询改写」。哪一句把路改错了？哪一句丢掉了约束？哪一句才是正确处理？各用一句话。

1. 住户刚问过 WO-3184，接着说「个水喉仲漏唔漏？」。系统把它改写成「厕所渗漏住户可以先做什么」，去翻了手册。
2. 住户说「取消 15A 的临时通行证」。系统改写成「如何申请临时通行证」，检索到了申请流程。
3. 住户用粤语问「点申请临时通行证」。系统改写成手册里的标题「申请临时访客通行证」，检索后引用了现行条款；模型先写过一段带「按金五十元」的假想通告，但没有把它写进答案，也没有拿来当引用。

## 自测

1. 这间屋苑。查询改写和查询路由差在哪？原话里的约束为什么必须留下来？HyDE 的假想文档能不能当证据？这一层要怎样验收？
2. 如果面试官来自虚拟银行，客户助手要处理「我刚才那笔转账到了没」和「现在转账限额是多少」。和这间屋苑相比，哪些问法最多只是还原交易号再查核心系统，哪些可以把口语对成产品说明再检索？为什么不能把「到了没」改写成「一般即时到账」并引用产品简介？

### 自测 1

差别：查询路由决定这条问题走哪条路，比如手册、工单系统、转人工或拒答。查询改写是上路之后，把原话变成这一路更好用的查询。先选路，再改写。

约束必须留下，是因为改写的目标是更好找，不是把问题换成一个更常见、更好答的题。「取消 15A 的临时通行证」如果变成「如何申请」，字更像手册，答案却是错的。改完要对回原问题，对不上就作废。

HyDE 的假想文档不能当证据，也不能给用户看。它只提供一个更接近文档口吻的向量，用来找真实片段。真正能写进答案和角标的，仍是检索到的现行材料；材料里没有的细节，不能用假想文来补。

验收不能只看最终答得像不像。冻结集里要有：指代必须带回单号并走系统的题、必须保留动作和户号的题、假想文档不得泄漏的题，以及换题后不得沿用上一轮对象的题。改写忠实度、检索质量、回答质量要分开统计。

### 自测 2

和屋苑里的「我的工单到边了」同类、必须带着交易号或客户号去查核心系统的：刚才那笔转账到了没有、可用余额、已出结单。这类问法的改写最多是还原「那笔」指哪一笔，然后走系统。不能改写成产品说明里的「一般即时到账」，更不能拿去命中共用缓存。

可以把口语对成现行产品说明再检索的：当前版本的转账限额、公开操作步骤。这一路改写后，仍要引用现行条款的具体段落和版本，见溯源。条款里没有新限额，就不能补一句「一般是五万元」。

把「到了没」改写成「一般即时到账」并挂上产品简介，既改错了路，也没有依据。听起来像已经核对过，其实查的不是这一笔。改完要用银行这类题重跑冻结集，不要只用屋苑通行证的例子交差。

## 一句话总结

> **查询改写是：路已经选定之后，把用户的原话变成这一路更好找的查询。** 它不决定去哪里办。原话里的约束必须留下；假想文档只用来检索，不能当答案。改写忠实度和回答质量要分开验收。
