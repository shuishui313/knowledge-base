**AI-04**

## 招聘切入

香港保险或银行的 FDE 面试，听到「Agent」时很少停在定义。他们接着问：这是单次工具调用，还是带着目标在循环？循环何时停？哪一步不能自动跑？

公开面经里的常见问法是：多步任务里模型怎么决定下一步、预算和停条件在哪、失败时怎样把控制权交回人。香港保险挂着 FDE 的岗位几乎没有公开逐字面经。下面仍用柜面跟进缺材料做教学案例，对得上「循环、停条件、留人」这些追问，不是某家公司的题目原文。

本系列的 [工具调用（Tool Calling）](AI-03-工具调用(Tool-Calling).md) 已经说过：单次查进度再回答，是工具调用，不必叫 Agent。这一篇把「目标还没完成时继续动手」写清楚。

## 定义

智能体（Agent），也常说 Agentic 系统 = 模型在一个还没完成的目标下，反复选择动作、观察结果、再决定下一步，直到满足停条件或预算用尽。动作通常是工具调用；也可以是再问用户一句、或把草稿交给人确认。

和单次工具调用的差别不在「会不会调工具」，而在「谁决定下一轮」。单次调用：应用或提示已经规定「问进度就调 get_claim_status，调完写回答」。Agent：下一步是再查、再问、写入，还是停下来，由模型根据上一轮观察来选——但仍在你划定的工具清单、权限和预算里。

四个零件缺一，就不要急着贴 Agent 标签：

| 零件 | 作用 | 缺了会怎样 |
|------|------|------------|
| 目标 | 还没完成的结果，例如「把这单缺材料跟到可提交」 | 每次回复只像聊天，不知道何时算完 |
| 工具循环 | 观察 → 选择动作 → 执行 → 再观察 | 退回成一次生成或一次固定流水线 |
| 停条件 | 成功、失败、转人工、或轮数/费用上限 | 可能空转，或把半成品说成办完 |
| 跨步状态 | 已查到的保单号、缺什么、上次错误 | 每轮从零猜，重复调同一接口 |

和本系列另外两篇的分工：

| 做法 | 控制逻辑在谁 | 典型场景 |
|------|--------------|----------|
| [RAG](AI-02-RAG检索增强生成(RAG).md) | 固定：先检索再生成 | 条款、手册里有没有这句话 |
| [工具调用](AI-03-工具调用(Tool-Calling).md) | 模型选工具，常是一轮或短链 | 读这一刻的进度字段 |
| Agent | 模型在目标下多轮编排 | 缺材料清单未齐时持续跟进，直到可提交或转人工 |

名字叫大了无害。把「会循环」理解成「可以自己改生产数据、自己对外承诺」就有害。循环里每一步的权限，仍是那个工具的权限；停条件写在应用里，不写在「请模型小心」里。

## 为何需要

有些任务的下一步依赖上一步的返回。客户说「这单材料齐了没、缺的话帮我列出来并记一笔催办」。先读进度，才知道缺什么；缺什么决定要不要写入催办；写入失败又决定是重试还是转柜员。把整段收成一次提示，模型容易用流畅中文跳步。

固定流水线也够用，但只在路径事先已知时：永远「检索 → 生成」，或永远「查 A → 查 B → 回答」。路径会分叉、会因错误改道时，把分支全写进 if/else 成本高，也难跟业务一起改。Agent 把「这一步之后做什么」交给模型，把「允许做什么、做几次、失败怎么办」留给你的程序。

它不因此什么都该 Agent 化。只读一个字段就回答，用单次工具调用更清晰，也更好测。没有停条件的循环，只是把幻觉和重复调用拉长。

## 进展与常见形态

研究里常一起提到的 ReAct（Yao 等人，ICLR 2023）把推理和行动交错：先想一步，做一个动作，看观察，再想。今天产品里的「Agent」多半是这个想法的工程化：工具清单 + 多轮对话状态 + 轮数或费用上限。

常见几层（名字各家不同，骨架相近）：

1. **单工具问答**：一轮调用，不是 Agent。
2. **短链编排**：模型连调两三次只读工具，仍有硬上限。
3. **带目标的循环**：明确成功/失败/转人工条件，状态跨轮保留。
4. **人在回路**：写入、对外发送、改结论前必须确认；模型可以提议，人不点头就不执行。

预算是停条件的一部分。轮数、工具次数、总耗时、总费用都要有上限。上限到了：说明「还没完成、卡在哪一步、建议人接手」，而不是再生成一段看起来像办完的话。

失败模式和工具调用同族，只是更长：

| 你看到的 | 实际发生了什么 | 回答不该怎样 |
|----------|----------------|--------------|
| 空转 | 两三个只读工具来回调，目标没推进 | 不要把「我已经检查过」说成已办完 |
| 跳步 | 没读到缺材料列表就写入催办 | 不要在观察为空时执行有副作用的工具 |
| 假完成 | 预算用尽，最后一句仍说「已帮您处理」 | 预算耗尽必须暴露，并列出未完成项 |
| 权限漂移 | 循环中途换了一把更宽的凭证 | 全程用同一调用者的权限 |

## 缓解与落地做法

落地时先写三张卡片，再接模型：目标是什么、工具边界、停条件。提示词里的「你是一个有用的助手」替代不了这三张卡片。

可以先写成这样再去调模型：

```
目标：在柜员权限内，把保单 P-18442 的缺材料跟到「可提交」或「需转人工」。
允许的工具：get_claim_status（只读）；list_missing_docs（只读）；create_followup_note（写入，需确认，幂等键=claim_id+date）。
禁止：拒赔、改理赔结论、向客户承诺批复日、用姓名猜保单号。
停条件：缺材料为空 → 成功停；同一错误连续 2 次 → 转人工；总轮数 > 8 或工具调用 > 12 → 预算耗尽停。
预算耗尽时：列出已确认事实、未完成动作、最后一次错误原文；禁止说「已处理完毕」。
```

### 一个柜面例子

虚拟的香港保险公司柜面。客户问：「P-18442 缺的材料跟一下，能提交了就告诉我，还缺就记一笔催办。」

合理循环可能是：

1. 调 `get_claim_status` → 仍是 `waiting_documents`。
2. 调 `list_missing_docs` → 缺「医疗收据正本」。
3. 向柜员确认后调 `create_followup_note`（幂等键挡住重复开单）。
4. 再读一次状态；若仍缺材料，停在「已记催办、仍缺收据」，而不是假装已提交。

若第 1 步超时：交回超时原文，不进入写入；对客户说这次没有返回进度。若模型没读列表就提议写入：应用拒绝，要求先有一次成功的 `list_missing_docs` 观察。

哪些可以自动跑，面试里要能当场分开：

| 动作 | 这一版 |
|------|--------|
| 读进度、列缺材料 | 可以自动跑；失败把原文交回 |
| 记催办 | 柜员确认后才写入；幂等键 |
| 宣布「可提交」、拒赔、承诺批复日 | 不自动跑；最多起草给柜员 |

保险柜面是这一篇的主例子。换公司，循环可以保留，自动和留人的分界线跟着副作用走：

| 公司类别 | 循环里可自动 | 必须等人 | 预算耗尽时 |
|----------|--------------|----------|------------|
| 虚拟银行 / 保险 | 只读进度与缺件 | 催办写入、改结论 | 列出未完成项，不说已办完 |
| 物流 | 读扫描与节点 | 改库存、通知改地址 | 说跟进未完成，不编到达时间 |
| 公营柜面 | 读预约/排队状态 | 销号、改跨部门作业 | 状态未知就保持未知 |
| AI 产品 / 解决方案公司 | 读客户允许的查询 | 提交、扣款、对外发送 | 公开面经会追问停条件与人工门闩 |

和幻觉、工具调用的关系可以直接说。[幻觉](AI-01-AI幻觉(Hallucination).md) 在多轮里更容易被「我已经查过」盖住：每一轮都要能指回观察，而不是指回上一句自信的计划。工具调用是手；Agent 是带着目标反复伸手——手仍然不能自己发明返回值。

## 面试怎么说

大约一分钟：

> “I only call it an agent when there is an unfinished goal, a tool loop, a stop condition, and state across steps. Reading claim status once is tool calling, not an agent. For missing documents I let the model loop on read tools, but writing a follow-up note waits for the officer, with an idempotency key. If the step budget is hit, I surface what is done and what failed. I do not let the model say the case is finished. At a public counter I would keep the same rule: reading the queue can loop; cancelling a ticket waits for a supervisor.”

现场用粤语跟柜员确认「这一步是查出来的，还是预算到了要人接手」。目标、允许的工具、停条件和人工门闩，用英文写进方案。

## 自测

1. 单次查保单进度，和「缺材料跟到可提交或转人工」，哪一个才需要 Agent？停条件和人工门闩你会写哪几条？
2. 若面试官来自 AI 产品公司，希望机器人多轮后直接帮用户提交；或来自公营柜面，希望系统在循环里直接销号。分界线怎样移动？物流呢？

### 自测 1

单次查进度：一轮工具调用即可，不必叫 Agent。缺材料跟到可提交或转人工：目标未完成、下一步依赖观察，才需要带停条件的循环。

停条件至少写：缺件为空则成功停；同一错误连续两次则转人工；轮数或工具次数上限到了则预算耗尽停。人工门闩：写入催办要确认；宣布可提交、拒赔、承诺批复日不自动执行。预算耗尽时列出已确认事实和未完成项，禁止说「已处理完毕」。

答到「单次调用≠Agent；目标+循环+停条件；写入等人；预算耗尽要暴露」即算完整。

### 自测 2

AI 产品或解决方案公司：只读查询仍可多轮自动跑。提交、扣款、对外发送留在确认之后，除非书面边界另有规定，且失败与预算耗尽仍要出现在对话里。面试官希望「直接帮用户提交」时，把提交留在门闩后，不把希望说成已经上线的权限。公开面经追问的就是停条件和人工门闩。

公营柜面：读预约或排队可以循环。销号、改跨部门夜间作业等主管确认。状态未知就保持未知。

物流：读扫描和节点可以循环。改库存、通知收货人改地址要等人。没有新记录就说跟进未完成，不编到达时间。

答到「副作用和对外承诺留人；只读可循环；三类公司预算耗尽都要暴露未完成」即算完整。

## 一句话总结

> **Agent 是带着未完成目标的工具循环，不是把聊天机器人改个名字。** 单次查询用工具调用；多步跟进才需要停条件、预算和人工门闩。循环可以自动读，不能自动把失败说成办完。
