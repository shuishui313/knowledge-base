**AI-23**

## 面试在问什么

物业报修助手已经会分流、改写，也会在召回之后做重排。可第一轮如果只走向量，新的问题常常是：对的材料其实在库里，却根本没进候选。

住户报了一个通告编号「TN-2026-08」。书面标题里清清楚楚有这个号，向量却把它和同年其他通告看成差不多，现行通告没有出现在前几十条里。另一次，住户用粤语问「临时通行证按金而家几多」，库里的标题是「访客临时通行证收费」。关键词对不上这几个字，只靠 BM25 也找不到。还有一次，团队说「两路都做了」，却把 BM25 分数和余弦直接相加；或者只过滤了向量这一路，过期通告从关键词一路混了进来。更糟的是，有人把「WO-3184 到边了」也丢进混合检索，手册里的「一般两小时内」又排到了前面。

面试官很少停在「我们同时用了关键词和向量」。公开面经里的常见问法围着这几件转：为什么不能只做向量检索？两路分数为什么不能直接加？权限和版本过滤要加在哪？什么问法根本不该走混合检索？条款号题和口语题要怎样分开验收？

只说「关键词加向量效果更好」，偏弱。能讲清混合检索是第一轮从全库召回、两路按排名合并而不是把原始分数相加、过滤必须两路都做、单号查询要走系统，并把「对得上编号的题」和「对得上意思的题」分开验收，才像 FDE。

[查询路由](AI-19-查询路由(Query-Routing).md) 决定这条路去不去检索。[查询改写](AI-21-查询改写(Query-Rewriting).md) 改善怎么找。这篇写第一轮怎样从全库取出一个够宽的候选集。取出来之后，才轮到 [重排序](AI-22-重排序(Reranking).md) 决定留下谁，再按 [引用与溯源](AI-20-引用与溯源(Grounding-and-Citation).md) 核对依据。向量这一路的原理见 [嵌入与向量检索](AI-08-嵌入与向量检索(Embedding).md)。整条链路见 [检索增强生成](AI-02-RAG检索增强生成(RAG).md)。

## 定义

混合检索（Hybrid Search）：对同一问法并行做关键词检索（常见是 BM25）和向量检索，再把两路的排名合成一份候选集。它改的是「第一轮从全库召回谁」，不是再搜一遍之后的重排，也不是查业务系统。

| 做法 | 决定什么 | 不是什么 |
|------|----------|----------|
| 关键词检索（如 BM25） | 按字面词项找到条款号、通告编号、产品代码、罕见专名 | 不是理解口语或同义改写 |
| 向量检索 | 按意思找到措辞不同、但说同一件事的片段 | 不是精确比对编号或短代码 |
| 混合检索 | 两路各取一份名单，按排名合并成够宽的候选集 | 不是把两路原始分数直接相加，也不是查工单或账户 |
| 重排序 | 在这份已经召回的候选里，决定哪几条进入提示词 | 不是补回混合检索没召到的块 |

两路的分数不在同一把尺子上：BM25 往往是没有固定上限的相关分，余弦通常在一个很小的区间里。直接相加或随便定一个权重，排出来的顺序没有业务含义。常见做法是互惠排名融合（Reciprocal Rank Fusion，RRF）：先丢掉原始分数，只看这条在各路名单里排第几，再用 1/(k + rank) 这类公式加总。两路都排得靠前的块会上升；只在一路里出现、但名次很高的块，也仍有机会进候选。k 是平滑常数，常见取值是 60，不必在面试里背得更细。也可以先把两路分数归一化再加权，平台有时把这个权重叫做 alpha。用哪种合并，都要在冻结集上验证，不能只看一条演示题。

## 一次请求里实际发生了什么

1. 先路由。查 WO-3184 进度的，这一路走工单系统，不要把系统结果和手册混进混合检索，见 [查询路由](AI-19-查询路由(Query-Routing).md)。
2. 若问法离书面标题很远，可以把改写后的句子交给向量；原句里的通告编号、条款号、产品代码仍留给 BM25。改写是给向量用的，不是把粤语题从评测集里删掉，见 [查询改写](AI-21-查询改写(Query-Rewriting).md)。
3. 两路在取候选时就要按权限、产品和生效版本过滤，见 [权限感知检索](AI-17-权限感知检索(Permission-aware-Retrieval).md)。只过滤一路，另一路仍可能把不该出现的材料送进合并。
4. 每一路取出一个较宽的名单，再用 RRF 或归一化加权合成「宽的 k」。这一步追求的是标准块在不在名单里，不是最终进提示词的那几条。
5. 重排只对这份已合并、已过滤的名单打分，留下进提示词的几条，见 [重排序](AI-22-重排序(Reranking).md)。混合检索补不了重排，重排也补不回这一轮没召到的块。
6. 留下的片段能不能支持结论，仍要按溯源核对；证据不足就明说或转人工，见 [引用与溯源](AI-20-引用与溯源(Grounding-and-Citation).md) 和 [人工在环](AI-15-人工在环(Human-in-the-Loop).md)。
7. 记下两路各自的名单、合并后的名单、过滤条件，以及后来有没有重排。事后才能分清是关键词没接上、向量没接上、合并把对的块挤掉了，还是召回没问题、错在后面，见 [可观测性](AI-16-可观测性(Observability).md) 和 [评测](AI-05-评测(Evaluation).md)。

## 会在哪里坏

常见不是「没做混合检索」，而是两路各做各的，或把合并当成已经答对了。

- **只走向量。** 通告编号、条款号、产品代码差一位，向量仍可能觉得很近。编号类问题要靠关键词接上。
- **只走关键词。** 粤语口语、同义说法、中英夹杂对不上书面标题，标准块进不了候选。
- **把两路原始分数直接相加。** 分数量纲不同，排出来的顺序没有业务含义。要按排名合并，或先归一化再加权，并在冻结集上验收。
- **只过滤一路。** 过期通告或别户材料从没有过滤的那一路进入合并，占了宽的 k 的名额。权限和版本要在两路取候选时都生效。
- **不该走检索的路也被送进来。** 「WO-3184 到边了」应查系统。拿手册 FAQ 做混合检索，容易答出「一般两小时内」。
- **中文分词没准备好。** BM25 若按空格或随意切字，书面标题和口语问法都可能对不齐。中文、英文、编号要能同时被切出来，评测集里也要有粤语和中英夹杂。
- **验收只看书面标准题。** 演示题里标题和问法几乎一样，看不出编号题会不会漏、口语题会不会漏。两类题都要在冻结集里，并且分开统计召回。

## 香港落地例子

继续那间虚构的沙田私人屋苑助手。数字、户号和通告编号都是编的，不代表任何机构。

住户问「临时通行证按金而家几多」。向量有机会对上「访客临时通行证收费」这份现行通告；BM25 不一定能对上「而家几多」这几个字。两路合并后，现行通告要出现在宽的 k 里，再交给重排留下。

住户直接报「TN-2026-08 系咩」。BM25 应当凭编号找到那份通告；向量可能带回同年其他通告。合并后，带这个编号的现行通告必须在名单里，不能只留下一份「看起来也在讲通行证」的旧材料。

住户问 WO-3184 到哪了，不要走混合检索。带着单号查工单系统，用返回的状态作答。手册里的处理时限可以稍后解释流程，但不能代替这一单此刻的进度。

验收时，冻结集里至少要有：口语或改写问法必须召回现行通告的题；只报编号也必须召回对应文件的题；措辞很像但已废止、两路都不得召回当依据的题；以及单号查询不得走文档检索、必须查系统的题。只拿「按金是多少」的标准书面题做演示，看不出这一层有没有坏。

四类雇主的差异（对照即可）：

| 雇主类型 | 这件事上的侧重点 |
|----------|------------------|
| AI 原生 / 产品公司 | 混合检索是带版本的链路一环；改合并方法、权重或某一路的宽度前，要用「编号题 / 口语题」和「过期材料不得召回」的冻结集做回归 |
| 大厂云与平台 | 托管检索若提供混合查询，要能配置两路、合并方式、过滤是否两路都生效，并在追踪里看到各路名单和合并结果 |
| 咨询与系统集成 | 把「两路都过滤再合并」、单号类问题不走文档检索、以及编号题和口语题分开验收写进范围；工时往往花在这些规则，而不是换一个更贵的向量模型 |
| 甲方企业内部（如银行、保险、地产） | 条款号和产品代码必须能被关键词接上；客户的口语问法仍要靠向量；账户、交易、工单的实时状态必须查系统，不能靠手册检索来「差不多」 |

## 面试怎么说

> "Hybrid search is the first-stage retriever, not the reranker. I run BM25 and vector search in parallel, then fuse the rankings — usually with reciprocal rank fusion — because a BM25 score and a cosine are not on the same scale, so I never add the raw numbers. BM25 is there for notice IDs, clause numbers, and product codes. Vectors are there for paraphrases and spoken Cantonese that don't share wording with the formal notice. Both legs apply permission and version filters when they retrieve; if I filter only after fusion, an unauthorized or expired document can take a slot. The fused list is a wide candidate set. A reranker then decides what enters the prompt, and grounding still checks whether those chunks support the answer. If a resident asks where WO-3184 is, we don't hybrid-search the handbook — we look up the work-order system. We evaluate recall on a frozen set that includes exact-ID questions, colloquial paraphrases, and queries that must not go to document search at all."

先把「两路召回，再按排名合并」说清楚，再强调分数不能直接加、过滤要两路都做、单号不走混合检索；用客户习惯的语言（粤语或普通话）讲清楚，用英文把结论写下来。

## 小练习

仍是上面那间虚构的屋苑助手。同事报了三句「我们已经做了混合检索」。哪一句补不回编号类材料？哪一句把合并或过滤做错了？哪一句才是正确处理？各用一句话。

1. 住户问 TN-2026-08 是什么。现行通告没有出现在向量检索的前几十条里。团队决定换一个更强的嵌入模型，希望它把编号排上来，没有接 BM25。
2. 系统把 BM25 分数和余弦直接相加，并且只在向量这一路按权限和版本过滤；过期通告从关键词一路进入了合并后的名单。
3. 同一句按金问题，两路都在已过滤的资料里取候选，再用 RRF 合并，现行通告进了宽的 k。住户问 TN-2026-08 时，BM25 接上了编号。住户问 WO-3184 到哪了，系统不走混合检索，直接查工单状态。

## 自测

1. 这间屋苑。混合检索和只做向量检索差在哪？为什么两路分数不能直接相加？权限过滤为什么必须在两路取候选时都做？哪些问法根本不该走混合检索？这一层要怎样验收？
2. 如果面试官来自虚拟银行，客户助手要处理「我刚才那笔转账到了没」、「而家 SWIFT 转账要几耐」，以及客户报出一个条款号。和这间屋苑相比，哪些问法不应走混合检索、必须查核心系统？哪些可以走混合检索，但必须同时接住条款号和口语问法？为什么不能只拿书面标准题验收？

### 小练习

1. **补不回编号类材料。** 通告编号对向量不稳定，换嵌入模型也不保证差一位的编号能被分开。该把 BM25 接上再合并，不是只改向量。
2. **把合并或过滤做错了。** 原始分数不在同一把尺子上，直接相加没有业务含义；只过滤一路，过期通告仍能从另一路进来。两路都要在取候选时过滤，再按排名合并。
3. **正确处理。** 口语题和编号题都能进宽的 k；工单进度走系统，不走混合检索。

### 自测 1

差别：只做向量检索时，意思接近的片段容易出现，条款号、通告编号和产品代码却可能漏掉或和相近编号糊在一起。混合检索并行走关键词和向量，再把两路名单合成一份够宽的候选，让编号类和口语类都有机会被召回。它仍然只是第一轮召回，不是重排，也不是最终答案。

两路分数不能直接相加，是因为量纲不同。BM25 和余弦不在同一区间，相加后的第一名没有业务含义。应按排名做 RRF，或先归一化再加权，并在冻结集上验证。

权限过滤必须在两路取候选时都做，是因为合并只会在已经取出的名单里做。一路没过滤，未授权或过期材料就会占名额，还可能排到前面。不能指望合并或事后再丢来补这一步。

不应走混合检索的，是要查这一笔此刻状态的问法，例如「WO-3184 到边了」。这类答案在工单或业务系统里，手册再像也不能代替。

验收要把编号题和口语题分开看召回，冻结集里还要有：过期或未授权材料两路都不得召回的题，以及必须走系统、不得进文档检索的题。不要只用最终答案好不好看来判断。

### 自测 2

和屋苑里的「WO-3184 到边了」同类、不应走混合检索、必须带着交易号或客户号查核心系统的：刚才那笔转账到了没有、可用余额、已出结单。这类问法的答案是这一笔此刻的状态，手册或旧说明再像也不能代替。

可以走混合检索的：当前版本的 SWIFT 转账时效、公开操作步骤，以及客户报出的条款号。这一路要让 BM25 接住条款号和产品代码，让向量接住「要几耐」这类口语；取候选时滤掉停用版本，再按排名合并。旧宣传页即使在向量一路很像，也不能当依据。

只拿书面标准题验收，会漏掉两类真实失败：条款号被向量看成「差不多」，以及粤语问法对不上书面条款。改完要用银行这类题重跑冻结集，不要只用屋苑按金的例子交差。

## 一句话总结

> **混合检索是：同一问法并行走关键词和向量，再按排名合成一份够宽的候选。** 它不能代替重排，也不能代替查系统。两路分数不要直接加；权限和版本要在两路取候选时都过滤。编号题和口语题要分开验收。
